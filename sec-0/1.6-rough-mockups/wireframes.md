# 1.6 rough-mockups：画面のラフ

一番大事な点：ネコが触っても、停止・スキップ・画面移動が一度も起きない（intent の「誤操作ゼロ」）。そのため、ネコの画面にはボタンもリンクも置かない。
対象：床に置いたタブレット（横向き）とスマートフォン（Q4）。人が付き添わず、複数のネコが同時に遊べる（Q2）。

## 画面の一覧

| 画面 | 誰の画面 | 中身 |
|---|---|---|
| S1 ログイン／新規登録 | 飼い主 | メールアドレス・パスワード・「ログイン」・「新規登録はこちら」。入力エラーは文章で、通信エラーは再試行ボタン |
| S2 ホーム | 飼い主 | 「ネコを遊ばせる」（大きく）・「記録を見る」・ログアウト。送り直しが続けて失敗したら「保存できていない記録があります」と「再試行」（Q9） |
| S3 遊び画面 | ネコ | 紐・しっぽ・猫じゃらしが動き回り（Q1）、ときどきネズミ。複数が同時に動く（Q2）。ボタン・文字・時計は一切出さない |
| S4 飼い主メニュー | 飼い主 | S3 で「α」を描くと開く。「遊びを終える」→ S5、「遊びに戻る」→ S3 |
| S5 遊びの結果 | ネコ | 「遊びが終わりました」、遊んだ時間、保存の状態。「α」を描いたときだけ S2 に戻る |
| S6 記録 | 飼い主 | 遊んだ日時と時間の一覧、（提案）直近 3 回の平均 |

## S3 遊び画面の反応

| ネコの動き | 反応 |
|---|---|
| 紐・しっぽ・ネズミに触る | 触られたものが「ビクッ」と素早く動く（Q1） |
| 何もない所に触る | 何も起きない |
| 複数の場所を同時に触る | それぞれ別々に反応する（Q2） |
| なでる・なぞる（α の形にならない） | 何も起きない |
| 一定時間どこにも触らない | 自動で終わり S5 へ（Q3）。上限時間はない（Q6） |

- 遊んだ時間：ネコが最初に触ってから最後に触るまで。YouTube を手元で測るときも同じ数え方にそろえる（Q8）
- スマートフォン：（提案）紐・しっぽの数を減らし、1 つずつを大きくする

## S5 保存の状態（Q9）

| 状態 | 表示 |
|---|---|
| 保存済み | 「記録しました」 |
| 保存待ち | 通信できなければ端末に保存して「保存待ち」。通信が戻ったら自動で送る |
| 失敗が続く | 「保存できていない記録があります」。S2 の「再試行」で送り直せる |
| 一度も触られなかった | 遊んだ時間 0 分、（提案）記録に残さない |

## 提案（次の段階で確定）

- S2 →（提案）遊び画面に入る前に一度、「α」の描き方の見本を出し、端末を床に置く数秒の待ち時間を入れる
- S4 →（提案）メニューを開いている間も遊びの時間は止めない。数秒操作がなければ自動で閉じる

## 未確認の点

- 「α」とみなす基準（一筆、最小の大きさ、形のずれの許容）
- ネコの動きが偶然「α」とみなされたときの影響（S3 なら S4 が開く、S5 ならホームに戻る）
- 飼い主が「α」を描いている途中に、ネコが別の場所に触ったときの扱い
- 自動で終わるまでの「触らない時間」の長さ（30 秒は例）
- 送り直しに何回失敗したら知らせるか
- 端末自体の操作（通知やホームに戻るスワイプ）でアプリから出ないようにする方法
- ネズミが出る頻度、紐・しっぽの動き方と速さ
- 「遊びを終える」をネコが押さないための工夫
