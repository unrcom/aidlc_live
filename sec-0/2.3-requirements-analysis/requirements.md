# 2.3 requirements-analysis：要件

出典の記号：`意図` は 1.1 の intent-statement、`IC-Q` は 1.1 の質問、`ラフ` は 1.6 の画面と流れ、`RM-Q` は 1.6 の質問、`RA-Q` はこの段階の質問。
ラフの「（提案）」のうち未確定のものは要件に入れず、「未確定の点」に残した。

## PoC で確かめること（意図）

- ネコが途中で止められずに、1 回 5 分以上遊び続けられる
- 触っても停止・スキップ・画面移動が 1 回も起きない
- 自分のネコ 1 匹で YouTube とアプリを 3 回ずつ試し、平均の遊んだ時間がアプリの方が長い
- 人が付き添わず、複数のネコが同時に遊べる（RM-Q2）

## 品質の要件

| ID | 要件 | 合格の基準 | 出典 |
|---|---|---|---|
| NFR1 | 誤操作ゼロ：S3・S5 では「α」以外のどんな触り方でも、停止・スキップ・画面移動が起きない | 自分のネコで 5 分以上を 3 回、0 回 | 意図、IC-Q2 |
| NFR2 | 自動ロックで遊びが止まらない | 自動ロック 2 分で、10 分遊んでも画面が消えない | 意図 |
| NFR3 | iOS（iPhone・iPad）と Android の両方で動く | iPad・iPhone・Android のタブレットとスマートフォンの 4 種類で FR1〜FR7 を満たす | RM-Q4、RA-Q4 |
| NFR4 | 保存待ちの記録は、アプリを閉じて開き直しても残る | 通信なしで終え、開き直して通信を戻すと一覧に出る | RM-Q9 |
| NFR5 | パスワードは暗号化した通信でだけ送り、そのまま保存しない。他人の記録は見られない | 通信とデータにパスワードがそのまま現れない。他人の記録は 0 件 | IC-Q6 |
| NFR6 | 飼い主の画面は、状態を色だけでなく文章で示し、読み上げで操作できる | S1・S2・S6 のエラーがすべて文章を含む。読み上げでログインから記録まで操作できる | ラフ S1・S2・S6 |

## 制約・前提・対象外

- 制約：課金なし（IC-Q6）。ストア公開なし、試すのは自分と知り合い（IC-Q5）。iOS と Android のアプリを用意する（RA-Q4）
- 前提 `[assumption]`：知り合いの端末には各 OS のテスト配布で届ける。端末自体の操作でアプリから出てしまう場合は「アクセスガイド」などを使ってもらい、NFR1 はその状態で測る
- 前提：YouTube の時間は各飼い主の判断で測ってアンケートで報告する（IC-Q11、IC-Q14、RA-Q8）。アプリの数え方（FR5.1）とそろわない場合がある
- 対象外：課金、ストア公開、ネコごとの記録（メモで代用、RA-Q2）、上限時間（RM-Q6）、YouTube の時間の入力（IC-Q14）、アンケートの機能（IC-Q11）

## 未確定の点（次の段階で決める）

- 「α」とみなす形の基準（FR3.1・FR3.4 を満たす値）
- 「α」を描いている途中にネコが別の場所を触ったときの扱い
- 自動で終わる秒数の範囲（FR4.2）
- 何回失敗したら知らせるか（FR7.3）
- ネズミの頻度、紐・しっぽの動きと速さ（FR2.2）
- ラフの提案を採るか：α の案内と待ち時間、メニューの自動で閉じる、直近 3 回の平均、結果画面を暗めにする
- 「遊びを終える」をネコが押さない工夫
